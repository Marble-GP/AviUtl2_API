# AviUtl2 API / Live Bridge 0.9.6

0.9.6 introduces safe local `.aup2` working copies and explicit synchronization
with the project already open in AviUtl2. Synchronization and saving remain two
separate user-controlled actions.

## Highlights

- `LocalProject.load()` retains unknown sections/keys, third-party Effects, and
  untouched raw document data while patching known edited sections.
- `LocalProject.apply(plan)` is atomic in memory and never writes to disk.
- `checkpoint()` creates a numbered sibling such as
  `project.ai-0001.aup2` without rebinding or overwriting the source.
- `save_as()` requires `overwrite=True` plus a matching destination SHA-256 to
  replace an existing file. `save_source()` defaults to no overwrite and only
  replaces the source with explicit `overwrite=True`, a matching load-time
  hash, and a backup by default.
- `SyncSession.bind(local, live)` compares current-scene settings, ranges, and
  normalized Aliases. `sync.apply(plan)` is the only synchronization trigger.
- Sync reports `clean`, `local_dirty`, `live_dirty`, `diverged`, or
  `incompatible`; pre-existing differences are never auto-merged.
- Live-success/local-failure is exposed as `SyncPartialApplyError`; `recover()`
  retries only the local in-memory commit after verifying both revisions.
- `LocalProject` now mirrors the common immediate text/shape/media/transform and
  Effect methods from `LiveProject`; Local, Live, and Sync share one search
  vocabulary and cardinality-safe selections.
- High-level Live video placement uses AviUtl2's native probe for media
  validation, duration, dimensions, and audio-track detection. When an audio
  track exists, a verified Alias fallback creates one combined video object
  with embedded audio explicitly enabled; video/audio Effect scopes, Alias
  readback, native PNG, and native PCM are then verified normally.
- Automatic parallel placement no longer treats SDK `layer_max` as a creation
  limit. That field is the highest currently occupied layer, so empty and
  sparsely populated scenes can safely allocate lower free layers.
- `SyncValidationError`, `SyncConflictError`, and partial receipts carry
  machine-readable recovery metadata. Final native-readback Local state is
  separate from the pre-apply simulation in `SyncResult`.
- Root imports provide `EditPlan`, `LocalProject`, `LiveProject`, `SyncSession`,
  `effect()`, `native_effect()`, and `linear()` as one agent-facing surface.
- `project.get_info` now includes nullable `project_file_path`. Event watch adds
  `project_loaded` and pre-save-only `project_saving`.
- Package, plugin, protocol changelog, and capability manifest are synchronized
  at 0.9.6. Existing `LiveClient`, `LiveProject`, semantic Effect profiles, and
  protocol v1 calls remain compatible.

## What changed from 0.9.5

| Area | 0.9.5 | 0.9.6 |
|---|---|---|
| Local `.aup2` work | Mutable model and direct serializer | Lossless `LocalProject`, atomic in-memory `EditPlan`, guarded checkpoint/save APIs |
| Local/Live coordination | Separate manual operations | Explicit `SyncSession.apply(plan)` with semantic bind, conflict states, recovery receipts, and no background synchronization |
| Agent entry point | Mainly module-specific imports | Root imports for `EditPlan`, `LocalProject`, `LiveProject`, `SyncSession`, `effect`, `native_effect`, and `linear` |
| Immediate editing | Live-focused | Matching Local/Live text, shape, media, transform, delete, search, and Effect methods |
| Queries | Backend-specific filters | Shared exact/partial text, file, Effect, layer, frame, overlap, name, and API-lock vocabulary with explicit unavailable-filter errors |
| Errors | Mixed exception payloads | Machine-readable `code`, `details`, `retryable`, and `required_action` on recoverable high-level errors |
| Video with audio | Native creation could leave embedded audio disabled | Native probe plus verified combined-object Alias fallback enables embedded audio and preserves video/audio Effect scopes |
| Automatic layers | SDK `layer_max` could be mistaken for the creation limit | Free-layer search correctly extends beyond the highest currently occupied layer |
| Saving | Direct serializer remained easy to reach | `checkpoint()` is the default; source replacement requires explicit `save_source(overwrite=True)` and hash/backup guards |
| Documentation | Live manual and examples | Short Agent API Card, unified Local/Live/Sync workflow, executable checkpoint/sync examples |
| Quality gate | Existing test suite | Repository-wide Ruff format/check, strict mypy, pytest, CTest, package build, and Twine validation in Actions |

### Intentional behavior changes

- `LocalProject.save_source()` does nothing unless `overwrite=True` is passed.
  This is an intentional safety change; use `checkpoint()` for the normal AI
  workflow.
- `add_audio()` does not expose visual transform arguments. Supplying them via
  generic `add_media(kind="audio")` is rejected before mutation.
- Sync is never implicit. Local memory and Live are changed together only by
  `SyncSession.apply(plan)`, and disk is changed only by a later explicit save.
- General text overlap is allowed by default. Subtitle overlap diagnostics run
  only for explicitly designated subtitle layers and policies.

- A real AviUtl2 0.9.6 session applied video, shape, text, and audio in one

  returned native PNG and non-silent PCM; and reverted the complete edit with

## Quick start

```python
from aviutl2_api import EditPlan, LiveProject, LocalProject, SyncSession, effect

local = LocalProject.load("project.aup2")
plan = EditPlan().add_text(
    "第一章",
    key="title",
    duration=90,
    y=-200,
    effects=[effect("glow", strength=50)],
)

with LiveProject.connect(pid=46016) as live:
    sync = SyncSession.bind(local, live)
    result = sync.apply(plan)
    png = live.render(result.objects["title"].primary.midpoint).png

receipt = local.checkpoint()
print(receipt.path)
```

`sync.apply()` updates AviUtl2 and the local in-memory copy, but does not create
or overwrite an `.aup2`. Only the final explicit `checkpoint()` writes a file.

For the shortest LLM-oriented contract, see
[`docs/AGENT_API_CARD.md`](../AGENT_API_CARD.md).

## Safety boundaries

- No background file watching or mutation.
- No automatic push, pull, merge, reload, save, or conflict resolution.
- No AviUtl2 host command for Open, Save, Save As, playback, export, or upload.
- GUI Undo changes Live only; the session reports divergence rather than
  guessing how to roll local memory back.
- High-level editing of multi-scene files fails closed until scene ownership is
  verified against a host-generated fixture. Checkpoint-only lossless handling
  remains available.
- Unknown project-format versions may be read and checkpointed losslessly but
  are not high-level edited.

## Compatibility

Protocol v1 changes are additive. A 0.9.5 client ignores the new response field
and event types. A 0.9.6 client can continue using a 0.9.5 plugin for ordinary
Live operations, but project-path/lifecycle capabilities will be unavailable.

The 1.0 gate remains blocked by official SDK support for scene CRUD/switch and
Undo/Redo execution.
