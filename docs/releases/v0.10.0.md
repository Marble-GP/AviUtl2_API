# v0.10.0 Release Notes

Released: 2026-09-26 (feature branch; tag when approved).

## Summary

0.10.0 completes the 2026-09-19 official SDK mirror adoption with scene
management, project files, asynchronous file export, object flags, stable
IDs, and MCP Phase 1. Every new SDK path is gated on the host version
gate 2011000 (AviUtl2 2.1.10) through the `sdk_scene_crud` host flag;
older hosts fail closed with explicit `SDK_METHOD_UNAVAILABLE` errors.
Unsupported operations stay non-exposed: scene delete/duplicate and
undo/redo answer `SDK_METHOD_UNAVAILABLE` and are hidden from the MCP
method catalog.

## Updates

### Scene CRUD and background color (host-gated, 2.1.10+)

- New methods `scene.list`, `scene.create`, and `scene.switch`.
- Scene background color is carried in `scene.get_current` /
  `scene.update_current` using the 0-255 RGBA convention.
- Scene mutations are revision-checked and non-undoable (explicit
  `confirm_non_undoable: true` on the wire).

### Project files (host-gated, 2.1.10+)

- New methods `project.create`, `project.open`, and `project.save`.
- The `show_confirm` parameter is set to `false` for automation; no modal
  confirmation dialog blocks the call.
- `project.open` roundtrip verified on a live host: reopening a saved
  `.aup2` restores revision, frame range, frame rate, and objects.

### Asynchronous file export (host-gated, 2.1.10+)

- New method `export.start(output_file, output_plugin)`. The host output
  plugin name is caller-supplied because the official SDK exposes no
  enumeration API (only `register_output_plugin`).
- Export completion is observed through the sequenced
  `edit_state_changed` event stream. The event payload is null; the
  recommended completion check combines event firing with
  `project.get_info` `edit_state` polling and an output-file existence
  probe.
- Verified on a live host: `MP4 Exporter (by えすご/Esugo)` produced a
  valid 2,197,661-byte MP4 (3.008 s, 1920x1080, 30 fps, one video + one
  audio track) in about one second of wall time.

### Object flags and stable IDs (host-gated, 2.1.10+)

- New methods `object.flag.get` / `object.flag.set` for the `group`,
  `camera`, and `clipping` flags. Writes are revision-checked with
  apply-before-value rollback and run in the edit section per SDK
  requirements.
- New methods `object.id.get` and `effect.id.get` return the SDK int64
  stable identifiers (`{id, scope}`).

### edit_state_changed events

- The sequenced `edit_state_changed` notification is registered for edit,
  preview playback, and file output transitions.

### MCP Phase 1 (bundled)

- The `aviutl2-mcp` entry point serves nine hub-spoke tools over stdio:
  `bridge_card`, `bridge_status`, `bridge_call`, `bridge_help`,
  `bridge_find`, `bridge_snapshot`, `bridge_render_object`,
  `bridge_render_object_audio`, and `bridge_watch_events`.
- Install with the `mcp` extra: `pip install 'aviutl2-api[mcp]'`.
- The MCP server runs on the agent host as a separate process and talks to
  ONE running AviUtl2 instance over the local Windows named pipe. The
  plugin itself never spawns MCP.
- Method exposure derives from the running host capability manifest and
  fails closed: unknown methods and unsupported features are rejected
  before any pipe traffic, and unsupported methods are hidden from the
  catalog entirely.
- Non-undoable calls require explicit `confirm_non_undoable=true`
  acknowledgment at the MCP layer.
- Verified end to end on a live host: initialize, tool listing, card,
  status (70 methods exposed), scene listing, and fail-closed rejection of
  `scene.duplicate`.

### Python client

- `LiveClient` gains `list_scenes`, `create_scene`, `switch_scene`,
  `create_project`, `open_project`, `save_project`, `start_export`,
  `get_object_flag`, `set_object_flag`, `get_object_id`, and
  `get_effect_id`, plus typed result models in
  `aviutl2_api.live.project_files`.

### Capabilities and release gate

- Static manifest: `protocol/CAPABILITIES_0.10.0.json` (SDK baseline
  `mirror-2026-09-19`).
- Release gate: `sdk_scene_crud` is satisfied on 2.1.10+ hosts. The only
  remaining 1.0 blocker is `sdk_undo_redo`.

## Migration

- No breaking wire changes; protocol v1 stays additive. Clients that only
  use 0.9.x features keep working unchanged.
- Feature-detect via `system.get_capabilities` -> `host.sdk_scene_crud`
  instead of checking the plugin version.
- The bridge still starts Disabled on a fresh AviUtl2 start; enable it in
  the Live Bridge status window (per-process permission, not persisted).

## Known constraints (unchanged)

- Undo/Redo, scene delete, and scene duplicate remain unsupported
  (`SDK_METHOD_UNAVAILABLE`; 1.0 release gate waits for `sdk_undo_redo`).
- Export plugin names cannot be enumerated through the SDK; document the
  installed plugin display name per machine.
- `edit_state_changed` payloads are null; poll `edit_state` for the exact
  transition value.
- Frame marks do not participate in the timeline revision hash; re-read
  `mark.list` after external GUI edits when it matters.
