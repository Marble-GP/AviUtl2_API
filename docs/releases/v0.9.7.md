# v0.9.7 Release Notes

Released: 2026-09-23 (feature branch; tag when approved).

## Summary

0.9.7 adopts the official SDK mirror dated 2026-09-05 and exposes native
effect reorder, native media trim, frame marks, and object-level rendering.
Every new SDK path is gated on the host version reported by `InitializePlugin`:
AviUtl2 2.1.3+ enables `move_effect`-based reorder and object rendering,
2.1.4+ additionally enables section-endpoint trim and frame marks. Older
hosts keep the verified 0.9.6 alias fallbacks and fail closed with explicit
errors instead of touching out-of-bounds SDK members.

## Updates

### Native editing (host-gated)

- `object.effect.reorder` now prefers `move_effect` on 2.1.3+. The object
  identity stays stable (no alias replacement round-trip). The response reports
  `reorder_backend` so callers can distinguish native from fallback.
- `media.trim` now moves section endpoints directly on 2.1.4+ for fixed-speed
  media. Collision preflight runs before the first mutation; a failed
  verification rolls back in LIFO order and restores the original state. The
  response reports `backend: "native"` and the response field
  `trim_fixed_speed` reports `sdk_move_object_section`.
- Multi-section media can be trimmed natively; the alias fallback remains for
  older hosts.

### Frame marks (host-gated, 2.1.4+)

- New methods `mark.list`, `mark.set`, `mark.clear`, `mark.move`.
- Limits: 256 marks, memo up to 1024 characters (single line, no NUL/newline).
- Marks are explicitly non-undoable: mutation methods require
  `confirm_non_undoable: true` and the response states it. Occupied frames are
  rejected (`MARK_SET_REJECTED` / `MARK_MOVE_REJECTED`); stale revisions are
  rejected (`STALE_PROJECT_STATE`) with rollback.

### Object-level rendering (host-gated, 2.1.3+)

- `render_object_frame(obj, frame=...)` returns a revision-bound PNG capture
  of one object (optionally with effects applied).
- `render_object_audio(obj, frame_start=..., frame_end=...)` returns stereo
  f32le PCM accumulated per frame with SHA-256 integrity validation.
- Both reuse the existing capture chunk protocol (`*_read_chunk`, `*_release`).

### Inspection and capabilities

- Effect item types 17-19 are reported as `number_group`, `group`, and
  `separator`.
- `system.get_capabilities` adds the `host` section (runtime version + feature
  flags) and the `marks` section (limits and gating).
- Static manifest: `protocol/CAPABILITIES_0.9.7.json` (SDK baseline
  `mirror-2026-09-05`).

## Migration

- No breaking wire changes; protocol v1 stays additive. Clients that only use
  0.9.6 features keep working unchanged.
- To use native paths, feature-detect via `system.get_capabilities` ->
  `host.sdk_move_effect` / `host.sdk_frame_marks` / `host.sdk_section_endpoints`
  / `host.sdk_object_rendering` instead of checking the plugin version.
- Note: on a fresh AviUtl2 start the bridge starts Disabled by design; enable
  it in the Live Bridge status window (per-process permission, not persisted).

## Known constraints (unchanged)

- Undo/Redo and scene CRUD remain unsupported (1.0 release gate).
- Project open/save and export remain unsupported.
- Frame marks do not participate in the timeline revision hash; re-read
  `mark.list` after external GUI edits when it matters.
